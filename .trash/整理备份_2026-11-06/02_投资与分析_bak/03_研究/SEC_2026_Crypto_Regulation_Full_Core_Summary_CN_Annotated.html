二、S7-2026-27 — Regulation Crypto Assets（加密资产监管规则）

2.1 文件性质与目标

这是 SEC（美国证券交易委员会） 于 2026-08-18 发布的拟议规则，文件编号：

  • File No. S7-2026-27
  • Release Nos. 33-11434; 34-106150
  • 标题：Regulation Crypto Assets（加密资产监管规则）
  • 页数：402 页

它试图建立一套专门针对某些涉及 Crypto Asset（加密资产）s 的 Investment Contract（投资合同）s 的发行和融资制度。

SEC（美国证券交易委员会） 在文件中的政策目标包括：

  • 为 Crypto 项目提供更适配的资本形成路径；
  • 降低传统证券发行制度与 Crypto 项目之间的错配；
  • 在支持创新与资本形成的同时保留投资者保护；
  • 建立一个更明确的 Token / Investment Contract（投资合同） 生命周期框架。

2.2 最关键的概念：Token 与 Investment Contract（投资合同） 分开处理

这份文件最重要的逻辑，不是简单回答：

> “某个 Token 是不是证券？”

而是把两个对象分开：

  1. Crypto Asset（加密资产） 本身
  2. 围绕 Crypto Asset（加密资产） 形成的 Investment Contract（投资合同）

拟议规则中的核心对象是：

> Covered Investment Contract（受覆盖投资合同）

其基本结构是：

  • 存在一个 Investment Contract（投资合同）；
  • 某个 Crypto Asset（加密资产） 是该 Investment Contract（投资合同） 所涉及的资产；
  • 该 Crypto Asset（加密资产） 本身不是 Security（证券 / 安全性，按语境）；
  • 没有其他资产是该 Investment Contract（投资合同） 的标的。

这意味着：

> Token 本身可以不是证券，但围绕该 Token 的融资安排、开发承诺、管理努力和投资关系可以构成证券法意义上的 Investment Contract（投资合同）。

2.3 Crypto Asset（加密资产） 的定义

拟议规则中的 Crypto Asset（加密资产），核心定义为：

> 记录在加密安全的 Distributed Ledger（分布式账本） 上的数字价值表示。

也就是说，Regulation Crypto Assets（加密资产监管规则） 的制度对象不是所有数字记录，而是与密码学安全的分布式账本相关的数字化价值表示。

三、两套发行豁免

Regulation Crypto Assets（加密资产监管规则） 提供两条核心融资路径：

  1. Startup Exemption（初创项目融资豁免）
  2. Fundraising Exemption（融资豁免）

可以粗略理解为：

小型、早期项目
    ↓
Startup Exemption（初创项目融资豁免）
    ↓
最高 $5M

更成熟 / 更大规模项目
    ↓
Fundraising Exemption（融资豁免）
    ↓
Tier 1（第一档）: $20M
Tier 2（第二档）: $75M

四、Startup Exemption（初创项目融资豁免）

4.1 融资上限

Startup Exemption（初创项目融资豁免） 的核心上限是：

> 最多 500 万美元

它是一个面向早期 Crypto 项目的轻量化融资豁免。

4.2 最长四年

Startup Exemption（初创项目融资豁免） 适用期从：

> 提交 Notice of Reliance（依赖豁免通知） 后开始。

结束时间为以下两者中较早者：

  • 四年期满；
  • 提交 Form TR（过渡报告表） / Transition Report（过渡报告）。

因此，它不是一个可以永久使用的融资豁免。

4.3 One-time Use：不能反复重启

Startup Exemption（初创项目融资豁免） 对同一个发行人及其关联方设置一次性限制。

不能针对：

  • 同一个 Subject Crypto Asset（目标加密资产）；
  • 或者与之 Substantially Similar（实质相似） 的 Crypto Asset（加密资产）；

不断重启新的四年窗口。

其监管目的很明确：

> 防止项目在四年期结束后，仅通过换名称、换包装或轻微修改 Token，再开启一轮新的 Startup Exemption（初创项目融资豁免）。

4.4 Issuer（发行人） 可以是什么主体

Startup Exemption（初创项目融资豁免） 下的 Issuer（发行人） 可以是：

  • Entity（实体）
  • Individual（个人）
  • Group（团体）

如果是 Group（团体），则成员需要共同满足相应要求，并进行必要认证。

4.5 不是“无监管 ICO”

Startup Exemption（初创项目融资豁免） 虽然比完整注册发行更轻，但不是过去那种由项目方自行决定披露内容的 ICO 模式。

发行人在开始融资前，需要将 Rule 103（第103条规则） 要求的信息：

  • 免费公开；
  • 放置在公开网站；
  • 在 Notice of Reliance（依赖豁免通知） 生效前或同时可访问；
  • 在适用期间持续保持可访问；
  • 发生重大变化时进行更新。

因此其本质更接近：

> Whitepaper（白皮书） + 标准化、强制化、持续更新的监管披露。

五、Rule 103（第103条规则） — Crypto 专门披露框架

Rule 103（第103条规则） 是整个 Regulation Crypto Assets（加密资产监管规则） 中非常关键的一部分。

它要求围绕 Crypto 项目披露：

  1. Covered Investment Contract（受覆盖投资合同）
  2. Offering（发行）
  3. Subject Crypto Asset（目标加密资产）
  4. Management / Related Persons / Conflicts（管理层 / 关联人士 / 利益冲突）
  5. Crypto Network / Application（网络 / 应用）
  6. Development Plan / Progress（开发计划 / 进度）
  7. Security / Source Code（安全性 / 源代码）
  8. Token Economics（代币经济学） / Allocation
  9. Governance（治理）
  10. Ecosystem（生态系统）
  11. Risk Factors（风险因素）

5.1 Investment Contract（投资合同） 披露

需要说明：

  • 项目团队到底承诺完成哪些关键工作；
  • 哪些工作属于 Essential Managerial Efforts（关键管理工作）；
  • 当前已经完成到什么程度；
  • 未来还需要哪些关键管理努力。

这使“项目方到底承诺做什么”成为正式监管披露对象。

5.2 Offering（发行） 披露

可能包括：

  • Offering（发行） 中发行的单位数量；
  • Purchase Price（购买价格）；
  • Offering（发行） 持续期限；
  • Purchaser Restrictions（购买者限制）；
  • 与融资有关的协议；
  • 发行费用；
  • Proceeds（募集资金）；
  • Use of Proceeds（募集资金用途）；
  • Whitepaper URL（白皮书网址）。

5.3 Token Economics（代币经济学） 披露

需要披露的重要内容包括：

  • Token Supply（代币供应量）
  • Pricing（定价）
  • Lockups（锁定期）
  • Distribution（分配 / 流通）
  • Insider Holdings（内部人士持仓）
  • Release Schedule（解锁时间表）
  • Mint Mechanics（铸币机制）
  • Burn Mechanics（销毁机制）
  • Historical Transaction Information（历史交易信息）

这意味着：

> Tokenomics（代币经济学） 正式成为证券披露体系中的监管对象。

5.4 Network / Application（网络 / 应用） 披露

需要说明：

  • Crypto Network（加密网络） 或 Application 的性质；
  • 计划实现的功能；
  • 开发计划；
  • 当前开发进度；
  • 团队还需要完成的关键任务。

5.5 Security / Source Code（安全性 / 源代码）

如果 Source Code（源代码） 是公开的，可能需要提供：

  • Source Code URL（源代码网址）；
  • 安全机制；
  • 技术风险；
  • 网络安全相关信息。

5.6 Governance（治理） / Insider（内部人士） / Conflict

还需要披露：

  • Governance（治理） 结构；
  • 管理层；
  • Related Persons（关联人士）；
  • Insider（内部人士）；
  • Insider Transfer Restrictions（内部人士转让限制）；
  • 利益冲突；
  • 对项目控制权具有重要影响的人员和安排。

六、Fundraising Exemption（融资豁免）

Fundraising Exemption（融资豁免） 面向更大规模融资。

其结构部分借鉴了 Regulation A（A 规章融资豁免）。

6.1 Tier 1（第一档）

Tier 1（第一档） 的融资上限为：

> 2000 万美元 / 12 个月

特点：

  • 融资规模高于 Startup Exemption（初创项目融资豁免）；
  • 财务披露要求较轻；
  • 一般不强制要求审计财务报表；
  • 如果发行人因其他原因已经取得 Audit（审计），也可能使用相关财务信息。

6.2 Tier 2（第二档）

Tier 2（第二档） 的融资上限为：

> 7500 万美元 / 12 个月

它承担更高的信息披露和财务要求。

因此可以粗略理解为：

> 为 Crypto 项目定制的 Regulation A（A 规章融资豁免） 式更大规模融资路径。

6.3 非 Accredited Investor（合格投资者） 也可以参与

Fundraising Exemption（融资豁免） 并没有把普通投资者完全排除在外。

对于非 Accredited Investor（合格投资者），拟议规则设置购买金额上限：

> Aggregate Purchase Price（累计购买金额） 不得超过其年收入或净资产两者中较高者的 10%。

对于非自然人，则对应：

  • Revenue（收入）
  • Net Assets（净资产）

两者中较高者的 10%。

该购买限制适用于 Fundraising Exemption（融资豁免） 下的 Tier 1（第一档） 和 Tier 2（第二档）。

七、Fundraising Exemption（融资豁免） 的持续报告制度

这部分非常重要，因为它使较大规模 Crypto 项目开始接近“轻量版公开公司”。

主要表格包括：

  • Form 1-CRYPTO（加密资产发行申报表）
  • Form 1-KC（年度报告表）
  • Form 1-SC（半年度报告表）
  • Form 1-UC（当前报告表）
  • Form TR（过渡报告表）
  • NOR（依赖豁免通知表）

7.1 Form 1-KC（年度报告表）

用于：

> Annual Report（年度报告） / 年度报告

发行人需要按年度持续披露。

7.2 Form 1-SC（半年度报告表）

用于：

> Semiannual Report（半年度报告） / 半年度报告

拟议规则中要求：

  • 半年度结束后一定期限内提交；
  • 文件讨论中涉及 90 天 的提交窗口。

7.3 Form 1-UC（当前报告表）

用于：

> Current Report（当前报告） / 当前报告

当发生重大变化、重大事项或需要及时更新的信息时，需要进行当前报告。

7.4 财务报表要求

Tier 1（第一档） 与 Tier 2（第二档） 在财务报表和 Assurance / Audit（鉴证 / 审计） 要求上存在差异。

总体上：

  • Tier 1（第一档） 较轻；
  • Tier 2（第二档） 要求更高；
  • Fundraising Exemption（融资豁免） 下的项目需要持续提供财务信息；
  • Tier 2（第二档） 更接近正式公开融资所要求的财务可靠性标准。

八、证券是否属于 Restricted Securities（受限证券）

拟议制度与 Regulation D（D 规章私募豁免）、Regulation Crowdfunding（众筹监管豁免） 等传统豁免存在一个重要差异：

> 在拟议 Regulation Crypto Assets（加密资产监管规则） 下发行的证券，不会简单按照传统私募逻辑全部成为 Restricted Securities（受限证券）。

这意味着 SEC（美国证券交易委员会） 试图让：

  • 更广泛的 Solicitation；
  • 非 Accredited Investor（合格投资者） 参与；
  • 更高的二级流动性；

能够进入这一新制度框架。

九、Rule 104（第104条规则） — Bad Actor Disqualification（不良行为者失格机制）

拟议规则并没有因为是 Crypto 专门制度就放弃传统证券法中的 Bad Actor（不良行为者） 筛查。

如果：

  • Issuer（发行人）；
  • 或 Rule 262(a)（第262(a)条规则） 覆盖的相关主体；

出现 Rule 262 意义上的 Disqualifying Event（失格事件），

则可能不能使用相关豁免。

这部分逻辑基本参照 Regulation A（A 规章融资豁免）。

对于某些发生在规则生效前的事件：

  • 可能不会直接导致 Disqualification；
  • 但仍需要 Disclosure（披露）。

因此：

> Crypto 专门发行豁免仍然保留传统证券法“Bad Actor（不良行为者）”过滤机制。

十、Rule 400（第400条规则） — Investment Contract Safe Harbor（投资合同安全港）

这是整份拟议规则中最重要的制度之一。

它试图解决一个长期存在的问题：

> 某个 Token 最初可能因为项目方的承诺、融资安排和管理努力而受到 Investment Contract（投资合同） 约束，但项目成熟之后，什么时候可以明确认为这种 Investment Contract（投资合同） 已经结束？

10.1 条件 A：Essential Managerial Efforts（关键管理工作） 结束

Issuer（发行人） 必须已经：

  • 完成所有承诺的 Essential Managerial Efforts（关键管理工作）；
  • 或永久停止这些 Essential Managerial Efforts（关键管理工作）；

并且：

  • 不再作出新的 Essential Managerial Efforts（关键管理工作） 承诺；
  • 也不打算重新作出这类承诺。

10.2 条件 B：提交 Form TR（过渡报告表）

Issuer（发行人） 需要向 SEC（美国证券交易委员会） 提交：

> Form TR（过渡报告表） — Transition Report（过渡报告）

Form TR（过渡报告表） 需要包括：

  • Issuer（发行人） Information；
  • 对相关 Covered Investment Contract（受覆盖投资合同） 的描述；
  • 对 Subject Crypto Asset（目标加密资产） 的识别；
  • 对 Rule 400（第400条规则） 条件满足情况的 Certification（认证 / 声明）；
  • 支持该 Certification（认证 / 声明） 的分析。

10.3 Rule 400（第400条规则） 的效果

当 Rule 400（第400条规则） 条件满足后：

> Covered Investment Contract（受覆盖投资合同） 被视为已经终止。

同时：

> Subject Crypto Asset（目标加密资产） 被视为不再受该 Investment Contract（投资合同） 约束。

这并不是说某个 Token 从一开始就永远不是证券。

而是建立一条更明确的生命周期路径：

融资
  ↓
Investment Contract（投资合同）
  ↓
项目方履行关键管理努力
  ↓
项目逐渐成熟
  ↓
Essential Managerial Efforts（关键管理工作） 完成 / 永久停止
  ↓
Form TR（过渡报告表）
  ↓
Investment Contract（投资合同） 终止

10.4 没有简单设置固定时间

Rule 400（第400条规则） Safe Harbor（安全港） 本身并不是：

> “持有三年后自动不是证券”

或其他固定时间豁免。

核心判断仍然围绕：

  • Essential Managerial Efforts（关键管理工作） 是否完成；
  • 是否永久停止；
  • 是否还有新的关键承诺；
  • Form TR（过渡报告表） 是否提交。

十一、Rule 500（第500条规则） — Qualified Purchaser（合格购买者） 与州证券法 Preemption（联邦优先适用 / 州法排除）

Rule 500（第500条规则） 试图处理州级证券法重复注册问题。

拟议规则中的 Qualified Purchaser（合格购买者） 概念包括：

  • Regulation Crypto Assets（加密资产监管规则） 下的 Purchaser；
  • 某些符合条件的 Covered Investment Contract（受覆盖投资合同） 二级交易中的购买者。

前提通常包括：

  • Issuer（发行人） 正确依赖相关豁免；
  • Issuer（发行人） 持续履行 Disclosure（披露） / Reporting；
  • Issuer（发行人） 仍保持 Current。

其目的之一是：

> 对某些州级 Registration / Qualification Requirements（注册 / 资格核准要求） 进行联邦层面的 Preemption（联邦优先适用 / 州法排除）。

这有助于减少：

> 联邦层面已经允许，但发行人仍然需要逐州重新注册

带来的合规摩擦。

十三、SEC（美国证券交易委员会） 34-106402 — Tokenized NMS Stock（代币化 NMS 股票） TSV（代币化证券交易场所） 临时条件豁免

文件：

  • SEC（美国证券交易委员会） Release No. 34-106402
  • File No. 4-927
  • 发布日：2026-09-17
  • 页数：60 页

并同时附带 Request for Comment（征求意见）。

13.2 两项核心豁免

这份文件同时提供两个关键豁免：

1. TSV（代币化证券交易场所） Exemption

对符合条件的：

> Tokenized Securities Venue（代币化证券交易场所） / TSV（代币化证券交易场所）

给予 Exchange Act（《证券交易法》） 下：

2. Covered Firm（受豁免流动性机构） Exemption

对符合条件的 AMM（自动做市商） 流动性提供者：

> Covered Firm（受豁免流动性机构）

> “Dealer” Definition 的临时条件豁免。

这两个豁免必须一起理解。

因为：

  • 如果 Venue 可以不注册 Exchange / ATS（另类交易系统）；
  • 但 LP（流动性提供者） 因持续做市被要求注册 Dealer；

那么 AMM（自动做市商） 仍然很难实际运行。

共五年。

等权力。

因此这是：

> 一个有时间边界、条件边界和规模边界的监管实验。

十五、什么是 TSV（代币化证券交易场所）

TSV（代币化证券交易场所） =

> Tokenized Securities Venue（代币化证券交易场所）

其基本逻辑是：

  • 把 Tokenized NMS Stock（代币化 NMS 股票） 的 Buyer / Seller 聚集到一起；
  • 通过 AMM Liquidity Pool（自动做市流动性池） 提供交易；
  • 对参与者设置准入标准；
  • 允许 Permissioned Participants（经许可的参与者） 使用该 Venue。

核心结构：

Tokenized NMS Stock（代币化 NMS 股票）
        +
AMM Liquidity Pools（自动做市流动性池）
        +
Permissioned Participants（经许可的参与者）
        +
Distributed Ledger（分布式账本）

十六、什么是 Tokenized NMS Stock（代币化 NMS 股票）

Tokenized NMS Stock（代币化 NMS 股票） 可以由：

  • 原上市公司；
  • 代表上市公司的主体；
  • 与上市公司无关联的第三方；

进行 Tokenization（代币化）。

但是，它不是所有“股票价格 Token”都可以。

文件明确排除仅提供合成价格敞口的产品，例如：

  • Tokenized Linked Securities（代币化挂钩证券）
  • Security-Based Swaps（证券型掉期）
  • 纯 Synthetic Exposure（合成敞口）

Rights / Warrants（权利 / 认股权证） 也不属于该核心定义范围。

因此更准确的理解是：

> Tokenized NMS Stock（代币化 NMS 股票） 要对应真实 NMS（美国全国市场系统） Stock 权利，而不是只跟踪股票价格。

十七、Tokenized Stock 可以与什么组成 AMM（自动做市商） Pair

符合条件的 Tokenized NMS Stock（代币化 NMS 股票） 可以直接与以下资产形成 Pair：

  1. 另一个 Tokenized NMS Stock（代币化 NMS 股票）
  2. Non-Security Crypto Asset（非证券型加密资产）
  3. Payment Stablecoin（支付型稳定币）
  4. Tokenized Money Market Fund（代币化货币市场基金）

例如理论上可以出现：

AAPL-token / Payment Stablecoin（支付型稳定币）
NVDA-token / Payment Stablecoin（支付型稳定币）
AAPL-token / MSFT-token
AAPL-token / Tokenized MMF

17.1 Pair 的边界

Non-Security Crypto Asset（非证券型加密资产） 或 Tokenized Money Market Fund（代币化货币市场基金）：

> 必须直接与 Tokenized NMS Stock（代币化 NMS 股票） 配对，才能进入这一豁免结构。

也就是说，该制度不是授权 TSV（代币化证券交易场所） 任意发展成普通 Crypto Exchange。

十八、AMM Liquidity Pool（自动做市流动性池）

TSV（代币化证券交易场所） 可以通过 AMM Liquidity Pools（自动做市流动性池） 运行。

典型结构包括：

  • Smart Contracts（智能合约）；
  • 两种或多种资产；
  • Pool 中维持一定资产比例；
  • LP（流动性提供者） 向池子提供资产；
  • LP（流动性提供者） 获得 Fees（手续费 / 费用）；
  • 可能获得 LP Token（流动性凭证代币） 或其他 Incentive。

因此 SEC（美国证券交易委员会） 在这里监管的不是传统订单簿复制品，而是真正允许：

> Automated Market Maker（自动做市商） 模式进入 Tokenized Securities 的监管实验。

十九、Public Permissionless Chain（公共、无需许可的区块链） + Permissioned Participants（经许可的参与者）

这是第二份文件最重要的技术结构之一。

一方面：

  • Smart Contract（智能合约） / Distributed Ledger（分布式账本） Application 要可审计；
  • 应部署在 Public Permissionless Distributed Ledger（公共、无需许可的分布式账本） 上。

另一方面：

  • TSV（代币化证券交易场所） Participant 必须是 Permissioned 的；
  • 需要完成 Verification / Credentialing（资格认证）；
  • 可以采用 Wallet Whitelist / Allow-list（钱包白名单 / 许可名单）；
  • 需要支持制裁、AML/CFT（反洗钱 / 反恐融资） 等合规要求。

因此其架构更准确地说是：

> Public Permissionless Blockchain（公共、无需许可的区块链） + Permissioned Securities Participation（经许可的证券市场参与）

而不是完全开放式 DeFi。

二十、TSV（代币化证券交易场所） 必须是 U.S. Person（美国主体）

使用该豁免的 TSV（代币化证券交易场所）：

> 必须是 U.S. Person（美国主体）。

同时仍然受到美国制裁制度约束，包括：

  • OFAC Sanctions（美国财政部海外资产控制办公室制裁） 等相关要求。

二十一、TSV（代币化证券交易场所） Public Notice（公开通知） 制度

TSV（代币化证券交易场所） 在开始运营之前，需要进行公开 Notice。

核心要求包括：

> 至少在运营前 30 Calendar Days（日历日） 在网站公开 Notice。

Notice 需要：

  • Plain English（通俗英语）；
  • 免费公开；
  • 描述 TSV（代币化证券交易场所） 的基本业务、运行方式和豁免依赖情况。

TSV（代币化证券交易场所） 还需要：

> 在一定期限内向 SEC（美国证券交易委员会） 通知其 Public Notice（公开通知）。

文件讨论中包括：

  • 运营开始前 30 天公开；
  • 在相关时点后约 1 Business Day（工作日） 向 SEC（美国证券交易委员会） 提交通知。

21.1 Notice 更新要求

不同类型变化对应不同更新周期。

包括：

5 Business Day（工作日）s 级别

例如：

  • 开始或停止支持某个 Tokenized NMS Stock（代币化 NMS 股票）；
  • 因 Volume Limit（成交量上限） 暂停或恢复某个 Tokenized Stock；
  • Issuer（发行人） 对第三方 Tokenization（代币化） 提出异议；
  • 发现某些 Materially Inaccurate / Incomplete Information（重大不准确 / 不完整信息）。

20 Calendar Days（日历日） 级别

对于：

> Material Operational Change（重大运营变化）

需要提前约 20 Calendar Days（日历日） 更新相关信息。

Quarterly（按季度）

某些：

> Non-Material Changes（非重大变化）

可以按季度更新。

二十二、第三方 Tokenization（代币化）：原上市公司拥有反对权

如果 Tokenized NMS Stock（代币化 NMS 股票）：

> 不是由原上市公司或其代表进行 Tokenization（代币化），而是由无关联第三方进行，

TSV（代币化证券交易场所） 必须向基础股票发行人发送：

> Issuer Notice（发行人通知）

22.1 30 天等待期

TSV（代币化证券交易场所） 不得立即上线。

需要至少等待：

> 30 Calendar Days（日历日）

22.2 Issuer Objection（发行人反对）

如果原上市公司在期限内提出反对：

> TSV（代币化证券交易场所） 不得将该 Tokenized NMS Stock（代币化 NMS 股票） 提供交易。

这意味着：

> 第三方 Tokenization（代币化） 并不能完全绕过基础股票的原发行人。

二十三、TSV（代币化证券交易场所） 不允许 Primary Issuance（一级发行）

TSV（代币化证券交易场所） 豁免主要解决：

> Secondary Market Trading（二级市场交易）

而不是：

> Primary Issuance（一级发行） / IPO。

因此：

  • 企业不能仅依赖 TSV（代币化证券交易场所） Exemption 直接在 Venue 上进行首次证券发行；
  • 相关证券本身仍然必须已经注册；
  • 或依赖其他合法 Securities Act（《证券法》） Exemption。

所以需要明确区分：

证券发行层
    ≠
Tokenized Secondary Trading Layer

二十四、Tokenized Stock 必须保留真实股票权利

TSV（代币化证券交易场所） 必须验证 Tokenized NMS Stock（代币化 NMS 股票） 与传统同类别基础股票拥有相同的核心权利。

包括：

  • Company Interest（公司权益）
  • Dividends（股息）
  • Voting Rights（投票权）
  • Liquidation Residual Rights（清算剩余财产权）

如果是第三方 Tokenization（代币化），还要确保：

  • Proxy Materials（代理投票材料）；
  • Issuer Communications（发行人沟通材料）；

能够传递给 Token Holder（代币持有人）。

并且原则上：

> 不能把这些发行人沟通成本转嫁给 Issuer（发行人） 或 Shareholder（股东）。

因此：

> Token Holder（代币持有人） 不能只是获得股票价格敞口，而应当获得相应证券权利。

二十五、Symbol Limit（标的数量上限） 与 Volume Limit（成交量上限）

SEC（美国证券交易委员会） 对这个实验设置了非常严格的规模限制。

25.1 Tier 1（第一档）

Tier 1（第一档） TSV（代币化证券交易场所）：

  • 最多 75 个 Symbols
  • 单只 Tokenized NMS Stock（代币化 NMS 股票） 的交易量：

- 不得超过该基础 NMS（美国全国市场系统） Stock 上一个月 Average Daily Share Volume / ADV（平均每日股票成交量 / ADV） 的 0.25%

25.2 Tier 2（第二档）

Tier 2（第二档） TSV（代币化证券交易场所）：

  • 最多 250 个 Symbols
  • 单只 Tokenized NMS Stock（代币化 NMS 股票） 的交易量：

- 不得超过基础 NMS（美国全国市场系统） Stock 上一个月 ADV（平均每日股票成交量） 的 2.5%

25.3 Affiliate Aggregation（关联机构合并计算）

如果存在关联 TSV（代币化证券交易场所）：

> 需要合并计算相关限制。

不能简单通过多个关联 Venue 拆分规模来规避上限。

25.4 超过 Volume Threshold（成交量阈值）

如果某只 Tokenized NMS Stock（代币化 NMS 股票） 超过交易量阈值：

> 需要暂停其交易。

文件还设计了：

  • 在满足条件后；
  • 经过一定期间；

重新恢复交易的机制。

其中讨论中包括：

> 暂停后约 3 个月 的恢复条件。

25.5 超过 Symbol Limit（标的数量上限）

如果 TSV（代币化证券交易场所） 超过允许的 Symbol 数量：

> 则不能继续依赖该豁免。

因此 Symbol Limit（标的数量上限） 与 Volume Limit（成交量上限） 都是豁免的硬边界。

二十六、交易数据公开透明

TSV（代币化证券交易场所） 需要公开 Transaction Data。

核心要求：

  • 以 USD Denominated（以美元计价） 方式表示；
  • 免费；
  • Public（公开）；
  • Machine-Readable（机器可读）；
  • 提供最近 30 天 的交易数据；
  • 交易发生后约 10 分钟内更新。

这意味着 SEC（美国证券交易委员会） 在这一实验中非常强调：

> 链上市场的可观察性与公开交易数据。

二十七、基础股票停牌 → Tokenized Stock 同步停牌

如果基础 NMS（美国全国市场系统） Stock 在 Primary Listing Exchange（主要上市交易所）：

  • Trading Halt（停牌）；
  • Suspension（暂停交易）；
  • 或因其他监管 / 市场原因停止交易；

对应 Tokenized NMS Stock（代币化 NMS 股票）：

> 必须同步停止交易。

TSV（代币化证券交易场所） 需要及时通知参与者。

因此：

> Tokenized Stock 不能脱离基础 NMS（美国全国市场系统） Stock 的市场状态独立运行。

二十八、TSV（代币化证券交易场所） 禁止杠杆与信贷

TSV（代币化证券交易场所） Exemption 并没有同时开放链上证券杠杆体系。

TSV（代币化证券交易场所） 不可以：

  • Borrow Securities（借入证券）；
  • Borrow Non-Security Crypto Assets（借入非证券型加密资产）；
  • Hypothecate（质押）；
  • Arrange Hypothecation（安排质押）；
  • 向参与者提供 Credit（信贷） 购买 Tokenized NMS Stock（代币化 NMS 股票）。

所以当前监管实验的重点是：

> Spot Onchain Securities（现货链上证券）

而不是：

  • Leveraged Securities（杠杆证券）；
  • Onchain Margin（链上保证金交易）；
  • Securities Lending DeFi（证券借贷 DeFi）；
  • Credit（信贷）-based AMM（自动做市商） Trading。

二十九、Books and Records（账簿和记录）

TSV（代币化证券交易场所） 必须保留大量 Books and Records（账簿和记录）。

内容可能涉及：

  • Orders（订单）；
  • Transactions（交易）；
  • Participant Screening（参与者筛查）；
  • Wallet Information（钱包信息）；
  • Fees（手续费 / 费用）；
  • Rebates（返佣 / 回扣）；
  • Trading Pauses（交易暂停）；
  • Trading Resumptions（交易恢复）；
  • 与运营、合规和市场活动有关的记录。

因此：

> 获得 Exchange Definition Exemption（“交易所”定义豁免） 并不意味着 Venue 不需要留下监管可审计记录。

三十、TSV（代币化证券交易场所） 不能宣称 SEC（美国证券交易委员会） 批准

TSV（代币化证券交易场所） 虽然获得豁免，但：

  • 并没有因此注册为 SEC（美国证券交易委员会） National Securities Exchange（全国性证券交易所）；
  • 也不能对外宣称 SEC（美国证券交易委员会） 对其进行 Approval / Endorsement。

其 Notice 需要明确说明类似以下事实：

  • TSV（代币化证券交易场所） 未注册为 National Securities Exchange（全国性证券交易所）；
  • 不受完整 Exchange Fair Access（公平接入） 规则约束；
  • 不受完整 Regulation NMS（全国市场系统监管规则） 体系约束。

三十一、Regulation NMS（全国市场系统监管规则） 的关系

在满足 TSV（代币化证券交易场所） Exemption 条件时：

> Venue 不被当作 Exchange。

因此：

  • 不需要注册为 National Securities Exchange（全国性证券交易所）；
  • 不需要仅因为该业务而按照 ATS（另类交易系统） 的完整方式运作；
  • 某些原本适用于 Exchange / ATS（另类交易系统） / Trading Center（交易中心） 的 Regulation NMS（全国市场系统监管规则） 义务不适用。

但是：

> 其他联邦证券法义务并没有消失。

例如：

  • Antifraud（反欺诈）；
  • Antimanipulation（反操纵）；

等仍然适用。

三十二、谁可以成为 TSV（代币化证券交易场所） Participant

文件结构允许不同类型参与者进入 TSV（代币化证券交易场所），例如：

  • Retail Participants（零售参与者）；
  • Institutional Participants（机构参与者）；
  • Registered Broker-Dealers（注册经纪交易商）；

但：

> TSV（代币化证券交易场所） 的豁免并不会自动改变某个 Participant 自己的监管身份。

也就是说：

  • Broker-Dealer（经纪交易商） 仍然要遵守其 Broker-Dealer（经纪交易商） 义务；
  • 其他主体仍然要遵守自身适用的监管框架。

三十三、Covered Firm（受豁免流动性机构） Exemption — AMM（自动做市商） LP（流动性提供者） 的 Dealer 豁免

如果一个机构：

  • 持续向 AMM（自动做市商） 提供 Tokenized NMS Stock（代币化 NMS 股票）；
  • 使用自有资本；
  • 频繁买卖；
  • 提供类似 Market Making（做市） 的功能；
  • 从 Fees（手续费 / 费用） / Incentives 中获利；

则可能触发 Exchange Act（《证券交易法》） 下的：

> Dealer Definition（“交易商”定义）。

因此 SEC（美国证券交易委员会） 同时提供 Covered Firm（受豁免流动性机构） Exemption。

33.1 豁免范围

Covered Firm（受豁免流动性机构） Exemption 只适用于：

> 与 TSV（代币化证券交易场所） Exemption 下 AMM（自动做市商） Pool 中 Tokenized NMS Stock（代币化 NMS 股票） 交易直接相关的活动。

不能把它理解为：

> 一张通用 Dealer Exemption（“交易商”定义豁免） License。

33.2 只能 Own Account

Covered Firm（受豁免流动性机构）：

> 只能进行 Proprietary / Own-account Trading（自营账户交易）。

也就是说：

  • 主要使用自己的资产；
  • 为 AMM（自动做市商） Pool 提供流动性。

33.3 不得托管客户资产

Covered Firm（受豁免流动性机构）：

> 不得持有或托管客户资产。

这进一步限制其业务边界。

33.4 Records

Covered Firm（受豁免流动性机构） 需要保留记录，包括：

  • 是否维持足够 Liquid Assets；
  • LP Activity（流动性提供活动）；
  • Agreements；
  • Incentives；
  • Fees（手续费 / 费用）；
  • Rebates（返佣 / 回扣）；
  • 其他与其流动性提供活动有关的信息。

33.5 Website Disclosure（网站披露）

Covered Firm（受豁免流动性机构） 需要公开披露：

  • 自己并非 Registered Broker-Dealer（注册经纪交易商）；
  • 可能与 TSV（代币化证券交易场所） / Issuer（发行人） / 其他主体存在 LP（流动性提供者） 或 Market-Making Agreement（做市协议）；
  • 可能获得：

- Fees（手续费 / 费用）

- Tokens

- Incentives

- Rebates（返佣 / 回扣）

33.6 向 SEC（美国证券交易委员会） 提交通知

Covered Firm（受豁免流动性机构） 还需要向 SEC（美国证券交易委员会） 提交通知，信息可能包括：

  • Business Model（商业模式）；
  • Risk Controls（风险控制）；
  • Regulatory Contact（监管联系人）；
  • LP Arrangements（流动性提供安排）；
  • Incentives；
  • Fees（手续费 / 费用） / Rebates（返佣 / 回扣）；
  • 是否存在 Statutory Disqualification（法定失格）；
  • 对 SEC（美国证券交易委员会） Staff 信息请求与监督的 Consent（同意 / 承诺）。

33.7 反欺诈和操纵规则仍适用

Covered Firm（受豁免流动性机构） 即使不因这些特定活动注册为 Dealer：

> Antifraud（反欺诈） 和 Antimanipulation（反操纵） 规则仍然适用。

所以：

> “Dealer Exemption（“交易商”定义豁免）” ≠ “Securities Law Exemption”。

三十九、从投资研究角度应继续拆解的产业链

如果后续目标是：

> 从法规变化中寻找美股 / Crypto 的潜在投资机会，

不应该直接从法规跳到：

> “利好哪个币？”

更有效的方法是先拆产业链。

39.1 Public Blockchain（公有链）

研究：

  • 哪些链满足：

- Public（公开）

- Permissionless（无需许可）

- Audit（审计）able

  • 哪些链具备机构级性能与合规工具；
  • 哪些链已经承载 Tokenization（代币化） / RWA（现实世界资产） / Stablecoin。

39.2 Tokenization Infrastructure（代币化基础设施）

研究：

  • 股票 Tokenization（代币化）；
  • Securities Tokenization（证券代币化）；
  • Corporate Action Mapping（公司行动映射）；
  • Rights Mapping（权利映射）；
  • Issuer Integration（发行人系统集成）；
  • Onchain Asset Lifecycle（链上资产生命周期）。

39.3 Transfer / Ownership Records（转让 / 所有权记录）

研究：

  • 股东名册；
  • Transfer Agent（过户代理机构）；
  • Onchain Ownership Record（链上所有权记录）；
  • Token Holder（代币持有人） 与传统 Registered Holder / Beneficial Owner（登记持有人 / 实益所有人） 的衔接。

39.4 Wallet / Identity（身份） / KYC（了解你的客户）

因为参与者是 Permissioned 的，所以需要：

  • Identity（身份）；
  • KYC（了解你的客户）；
  • AML（反洗钱）；
  • OFAC Screening；
  • Wallet Whitelist / Allow-list（钱包白名单 / 许可名单）；
  • Credential Infrastructure。

39.5 Stablecoin / Tokenized MMF

因为 TSV（代币化证券交易场所） 允许：

  • Tokenized Stock / Payment Stablecoin（支付型稳定币）；
  • Tokenized Stock / Tokenized MMF；

所以需要研究：

  • 哪些 Stablecoin 可能成为核心 Pair Asset；
  • 哪些 Tokenized MMF 可以承担现金管理、结算和流动性功能；
  • 哪些发行人拥有合规与机构网络优势。

39.6 AMM（自动做市商） / DEX Technology

研究：

  • 哪些 AMM（自动做市商） 技术可以支持证券；
  • Permissioned AMM（自动做市商）；
  • Whitelisted Pool（白名单流动性池）；
  • Institutional DEX Infrastructure（机构级去中心化交易所基础设施）；
  • Smart Contract Audit（智能合约审计）；
  • Onchain Market Surveillance（链上市场监控）。

39.7 Custody（托管）

研究：

  • Securities Custody（证券托管）；
  • Crypto Custody（加密资产托管）；
  • Tokenized Asset Custody（代币化资产托管）；
  • Institutional Wallet（机构钱包）；
  • Qualified Custodian（合格托管机构）；
  • Broker / Custodian Integration（经纪 / 托管系统集成）。

39.8 Broker / Dealer（经纪商 / 交易商）

研究：

  • 哪些传统 Broker-Dealer（经纪交易商） 可能接入 TSV（代币化证券交易场所）；
  • 哪些机构可能成为 Covered Firm（受豁免流动性机构）；
  • 哪些机构可能提供 LP（流动性提供者） / Market-Making；
  • 哪些传统业务可能迁移到链上。

39.9 Listed Companies

研究：

  • 哪些上市公司可能主动 Tokenize 自己的股票；
  • 哪些公司可能反对第三方 Tokenization（代币化）；
  • 哪些公司可能成为早期 Onchain Capital Markets（链上资本市场） 的参与者；
  • 哪些交易、清算、托管、经纪公司可能因此重新定价。

四十一、状态提醒

S7-2026-27 目前仍是 Proposed Rule（拟议规则）。

Startup Exemption（初创项目融资豁免）、Fundraising Exemption（融资豁免）、Rule 400（第400条规则） Safe Harbor（安全港）、Rule 500（第500条规则） 等都不能当作已经最终生效的规则使用。

后续正式规则可能修改：

- 金额上限；
- 披露内容；
- Transition 条件；
- 报告义务；
- Definitions；
- Safe Harbor（安全港） 条件。
SEC（美国证券交易委员会） Release 34-106402 已于 2026-09-17 发布并生效。

TSV（代币化证券交易场所） 与 Covered Firm（受豁免流动性机构） 的临时条件豁免当前有效期为：

2026-09-17 → 2031-09-17

但 SEC（美国证券交易委员会） 保留在期间修改条件、范围或期限的权力。

四十二、最终一句话理解

> 第一份文件在解决“Crypto 如何合法融资并逐步脱离 Investment Contract（投资合同）”；第二份文件在解决“传统股票如何在公共链上通过 Permissioned AMM（自动做市商） 进行二级交易”。

>

> 两者合在一起，构成美国监管体系尝试搭建 Onchain Capital Markets（链上资本市场） 的两条主要制度路径。
