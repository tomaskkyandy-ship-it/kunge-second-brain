# 🚧 切斯特顿的栅栏 (Chesterton's Fence)

> **核心定义**：路遇一道看似无用的栅栏时，**改革者若不清楚它当初为什么被建在这里，就绝不能贸然拆掉它**。

---

### 🧠 底层逻辑

* 源自 G.K. 切斯特顿 1929 年的寓言
* **每一个现存的制度、规则、代码、习惯，都曾经解决过某个真实问题**——即使你现在看不到那个问题
* 拆掉的成本，往往在你拆掉的**那一刻之后**才显现
* 这不是反对改革，而是要求**先理解，再修改**

---

### ⚠️ 常见踩坑场景

| 场景 | 典型误判 |
| :--- | :--- |
| 接手新工作 | 「这个流程好蠢」→ 删掉 → 两周后某个事故暴露它存在的理由 |
| 重构代码 | 删掉「看起来没用」的兼容逻辑 → 老用户全部报错 |
| 修改习惯 | 戒掉一项「浪费时间」的例行公事 → 失去了它带来的缓冲或社交 |
| 阅读经典 | 「这本书过时了」→ 跳过 → 错过了它解决的原始问题 |

---

### 🛠️ 10 分钟拆除 SOP

在废除任何旧规章、旧代码、旧工作流前，先花 10 分钟做三件事：

1. **问人**：直接问当初建立它的人
2. **翻档**：查历史文档 / Git 提交记录 / 旧邮件 / 会议纪要
3. **推演**：设想它消失一周会发生什么

> 若确认当初的背景需求已因新技术而消失，**再自信且无风险地拆除**。
